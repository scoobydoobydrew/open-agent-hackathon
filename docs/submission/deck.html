The problem

A tumour cell can survive radiation. An LLM will happily tell you how to stop it, right or wrong

After radiation, a tumour with working p53 stops its cell cycle and repairs instead of dying.

Which genes should we switch off so the cell commits to apoptosis? The combinations explode and every wrong guess is a wasted experiment.

Why it works

A failure tells us what to try next, so the search cannot miss

1 · A knockout fails

The solver returns the surviving state and the genes active in it.

2 · Only those genes can break it

Adding a gene that is already off changes nothing.

3 · So extend only with them

Nothing is skipped: every minimal solution is found, or the queue runs dry and impossibility is proved.

Sponsors, limits, next

Built on the sponsor stack, upfront about its limits

Sponsor tech
  • Zetaris data layer: 3 tables over REST, LLM-written run_sql, SQL JOIN
  • Nemotron: proposals, SQL and explanations; thinking off after we measured it (268 s vs 2 s)
  • Meterless H-MEM: official engine, unmodified, 13/13
  • Built with Claude Code
Honest limits
  • In-silico hypotheses on one published model, not clinical claims
  • Solutions are loss of tumour suppressors: no drug. No DNA-damage-response target appears, so the model misses mechanisms
  • Exact engine: about 21 free nodes. A 53-node model returned UNKNOWN
Next
  • Symbolic (BDD/SAT) attractor backend with an engine router
  • Validate against published knockouts and CRISPR screens
  • Tumour mutation profile → scenario, druggable-only search
  • Same solver, other models and LLMs

The takeaway: a system that proves what it claims, and says “impossible” when it is.
