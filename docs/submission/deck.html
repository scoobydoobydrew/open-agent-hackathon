The problem

A tumour cell can survive radiation. An LLM will happily tell you how to stop it, right or wrong

After radiation, a tumour with working p53 stops its cell cycle and repairs instead of dying.

Which genes should we switch off so the cell commits to apoptosis? The combinations explode and every wrong guess is a wasted experiment.

Who it is for

Computational oncology and radiobiology groups choosing which knockouts to test, target-discovery teams that need a ranked and explained shortlist, and reviewers who must be able to check the reasoning.

Why it works

A failure tells us what to try next, so the search cannot miss

1 · A knockout fails

The solver returns the surviving state and the genes active in it.

2 · Only those genes can break it

Adding a gene that is already off changes nothing.

3 · So extend only with them

Nothing is skipped: every minimal solution is found, or the queue runs dry and impossibility is proved.

Sponsor technology

Three sponsors, each doing real work in the loop

Zetaris
the data layer
  • Network rules, scenarios and drug evidence are 3 SQL tables in open_agent
  • The LLM writes its own run_sql queries; a guard allows one SELECT on our tables
  • A SQL JOIN ranks candidate genes. Benchmark answers are kept out of the tables
Meterless
Nightshift + H-MEM engine
  • Nightshift is the primary AI provider: every request goes through the local runtime, and the model that answered is logged
  • H-MEM, official and unmodified, is the memory: store, ranked recall into the next prompt, feedback, audit ledger
  • Test: 12 tests, conformance 13/13
NVIDIA Nemotron
the model, reached through Nightshift
  • nemotron-3.5-lightning-30b-a3b proposes knockouts, writes SQL, words explanations
  • The NVIDIA key stays in Nightshift, never in the project
  • Measured: thinking on 268 s, off 2 s. The 550B model words better (99.4% vs 94.6% clean) but proposes no better

What is unique: nobody in the loop is trusted. The model writes SQL but a guard validates it, proposes knockouts but an exact solver judges them, and the memory keeps only solver-verified facts.

Limits and future enhancements

Upfront about the limits, clear about what comes next

Honest limits
  • In-silico hypotheses on one published model: not medical advice, expert and lab review required
  • Solutions are loss of tumour suppressors: no drug. No DNA-damage-response target appears, so the model misses mechanisms
  • Exact engine: about 21 free nodes. A 53-node model returned UNKNOWN
  • On this network the search needs no LLM: the LLM adds interface, SQL and checked wording
Future enhancements
  • Symbolic (BDD/SAT) attractor backend with an engine router, for larger networks
  • Validate against published knockouts and CRISPR screens
  • Tumour mutation profile becomes the scenario; druggable-only search
  • More Meterless engines (World Model, Markovian) and other models behind the same solver

The takeaway: a system that proves what it claims, and says “impossible” when it is.
